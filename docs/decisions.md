# 设计决策（稳定结论）

> 本文记录**大概率不会变动**的结论：目标、选型、边界。随时可变的东西（当前进度、待办）放 `AGENTS.md`。
> 定稿：2026-11-06。其中「免费资源现状」类内容有时效性，变化时回头修订。

## 1. 目标一句话

为 ICPC/CF/AtCoder 英文题面阅读训练做一个**全免费、零服务器**的工具：
每天（或手动）取一道 rating ∈ [1400, 1800]（可配置）的英文原题，自动生成「题面 + 生词表 + 句式命中 + （可选）双语对照」的静态页面。
使用对象：本人 + 队友（小团队），共用同一个 Pages 站点，无账号（已知词存各自浏览器，见 §5）。

## 2. 问题定位（为什么读题难）

按优先级假设：

1. **生词**（用户 2026-11-06 确认：语法没问题，卡在词汇）。CP 词汇高度重复（permutation, modulo, guaranteed, distinct, contiguous…），1400–1800 段位的叙事型题面词汇面更广。→ **生词表是第一优先级**。
2. **八股句式**：题面是固定套路的「方言」——"It is guaranteed that…"、"print any valid answer"、"modulo 10^9+7"、"0-indexed"、"It can be shown that…"。有限集合，背完受益终身。→ 第二优先级（实现便宜，正则匹配即可），对语法稍弱的队友仍有价值。
3. 长难句：机翻可缓解，但已被免费浏览器扩展解决（见 §6）。

**推论：「双语对照」是免费商品，「生词表 + 句式」才是自建价值；用户瓶颈在词汇，生词表优先。**

## 3. 形态选型

结论：**生成器与外壳分离**。

- 核心 = 一个 Python 生成器：输入（指定题号 或 "今天的题"），输出一个自包含静态 HTML。本地随时可跑，无在线依赖（除抓题面本身）。
- 外壳 = GitHub Actions 定时跑生成器 + GitHub Pages 展示。外壳坏了不影响核心。
- 路径：先做核心（纯本地 MVP），手动跑一两周验证有用，再挂 Actions + Pages。

| 形态 | 每天 | 手机可看 | 历史积累 | 备注 |
|---|---|---|---|---|
| A. Actions + Pages | ✅ 自动 | ✅ 浏览器 | ✅ git 历史 | 公开仓库免费；cron 会延迟、偶发跳过 |
| B. 纯本地脚本 | ❌ 靠人 | ❌ | 弱 | 最低成本，即核心生成器 |
| C. 安卓 APP | ✅ | ✅ | 自建 | 工作量数量级不对，**不做**（手机浏览器开 Pages 即可） |

版权备注：题面版权归出题人。个人学习用途、低调公开重分发，业内普遍接受；若日后想大范围传播，改为只公开词表/句式，原文不放。

## 4. 数据源

- **Codeforces 优先**：
  - `codeforces.com/api/problemset.problems`：全题库 + rating + tags，免费无鉴权（限速约 1 req/s）。实现"选 rating ≤ X 且没做过的题"足够（做过与否查 `user.status`）。
  - 题面本体 **API 没有**，需抓 `codeforces.com/problemset/problem/{contestId}/{index}` HTML：带正常 User-Agent、低频（每天一两页无压力）、失败重试，可换备用镜像（m1.，不保证常驻）。
  - 公式保留原 LaTeX，页面挂 KaTeX/MathJax CDN 渲染。
- **AtCoder 备选**：无官方 API；用 kenkoooo AtCoderProblems 公开 JSON（题号 + 难度），题目页面自带英文 tab 可抓，抓取放慢、礼貌。

## 5. 词表方案（两个"词表"，勿混淆）

**A. 今日生词表（每题一份，是输出）**
- `wordfreq`（pip，MIT，离线 Zipf 频率）过滤：分词 → 去数字/符号/变量型 token → Zipf < 阈值（**默认 4.0，2026-11-07 由 3.5 上调试行一周**，覆盖 graph/array 这类中频 CP 词，噪音靠"已认识"消化）→ 按 Zipf 升序输出；单复数合并、剔人名/公式/代码。
- **保底**：筛出不足 `--min-words`（默认 5）个时，按 Zipf 从低到高用阈值外的词补足并标「补」——一眼区分真·罕见词与保底词。
- **释义走 ECDICT 离线词典**（github.com/skywind3000/ECDICT，开源）：`scripts/build_dict.py` 一次性构建 `data/ecdict-subset.json`（构建时只把当页命中词条打进页面）。零 API、零网络、国内无障碍。2026-11-07 替换掉 dictionaryapi.dev（国内被墙、CP 词覆盖差）与 Google 翻译兜底链接（同样被墙）。
- **题面内文高亮**：生词用低饱和淡黄底（与灰色样例代码块区分），已认识的词高亮变灰，带总开关；只处理普通文本节点，不碰公式/代码段。2026-11-07 定案。

**B. 已知词记忆（跨题累积，是输入）** —— 解决 "permutation 下周又进生词表" 的问题
- 存**浏览器 localStorage**。交互（2026-11-07 晚重构）：**点词身 = 看 ECDICT 释义**；**✓ 按钮 = 标记已认识**——已认识词**不隐藏**，留在列表里变灰划线（内文高亮同步变灰），让跨页记忆可见。ⓘ 与 ☆ 按钮已删除（☆ 原服务于沉底机制，随沉底一起失业）。
- ~~见过 ≥3 次自动沉底~~ 2026-11-07 移除：实测它等价于"页面打开次数"（同页所有词同步 +1），零区分度。若日后需要，改成"出现过的天数"计数（每词每天最多 +1）。
- 多人共用天然按浏览器隔离，队友互不干扰，无需账号。
- 换机不迁移（2026-11-07 用户拍板）：已知词只存本浏览器，换设备从零点起——词量小，成本可忽略；导出/导入 JSON 已去掉（见 §7）。
- 不做初始种子，从零开始点：头两周列表偏长、逐日变短，本身即进步曲线。

**C. 句式库（第二优先级）**：`phrases.md` 人工积累 + 每篇题面正则匹配命中并高亮。

**D. 历史词频统计（v2 第一位，2026-11-07 提级）**：聚合 `problems/*/words.json`——口径是**已过滤的生词表**而非原文全文，不怕 the/of/to 霸榜；排除已认识，按**出现天数**排序 → "CP 八股生词榜"。

顺手项：生词表导出 Anki CSV（纯文本，免费）。

## 6. 翻译策略（双语，段落级；随 Actions 外壳上线）

- **构建时翻译**：GitHub Actions 构建机在境外，调**非官方** Google 翻译接口（`translate.googleapis.com/...?client=gtx`，无 key、无注册）通畅；译文**烤进静态页面**。读者浏览时零翻译请求——谷歌被墙只影响构建机，不影响国内读者。一天一道题几千字符，远够非官方接口的量；真挂了还有 MyMemory、非官方微软接口等无 key 备胎。
- **呈现 = 折叠**：默认隐藏、点段落展开（或整页开关且默认关）。中英并排常驻会导致只读中文，练不了读。
- 本地（国内）跑脚本时谷歌不可达：**本地版无译文属预期行为**，译文能力随 Actions 外壳上线。
- 明确排除（2026-11-07）：DeepL 免费 tier（要绑卡注册，key 放前端等于泄露）、一切客户端直连的翻译/词典 API（被墙或 key 泄露）。
- 兜底：沉浸式翻译扩展（选国内可达的微软源）。

## 7. 明确不做（scope-out）

安卓 APP、账号/登录、已知词云端同步与导出/导入（2026-11-07 去掉）、付费 API（翻译或 LLM）、客户端直连翻译/词典 API（被墙或 key 泄露）、自动判题/提交代码、独立"做过题"同步（直接查 CF `user.status`）。

## 8. Open questions（待定；定了移入正文）

- 站点可见性：默认公开即可（个人学习重分发灰度小，队友共用不受影响）。

已定（2026-11-06）：rating 区间 [1400, 1800]，题源为该区间**全库随机**（不限制 Div.2/3 A–C）；生词优先于句式；本人 + 队友共用；已知词用 localStorage 从零积累；词频阈值默认 Zipf < 3.5（`--zipf` 可调）。

已定（2026-11-07，试用反馈）：释义走 ECDICT 离线词典；去掉自动沉底；内文淡黄高亮 + 开关；`--min-words`（默认 5）保底补充；历史词频统计提为 v2 第一位；双语 = Actions 构建时翻译 + 折叠呈现。

二次定案（2026-11-07 晚）：Zipf 阈值上调至 **4.0 试行一周**；交互重构（点词=看释义、✓=标记已认识且不隐藏、☆/ⓘ 删除）；已知词可见化（折叠行/计数器）推迟到做全局词库（v2）时一并考虑；trans.json 入库后本地重渲染可复用 CI 译文。
